# AAA Glossary

- **postbox** — the immutable, hash-chained, append-only queue of operator-signed change requests that cloud maintains per device target; devices poll it, cloud never pushes to it (§5.3).
- **head checkpoint** — `{tenant/target, max_id, hash_of_head, time, sig}`, signed by pki-core and RFC 3161-timestamped, short TTL; a device rejects any checkpoint below its high-water mark or past TTL (stale ⇒ fail-safe), which catches a cloud lying inconsistently about the postbox tail (§5.3, D8).
- **high-water mark** — the monotonic ID a device has already seen in its postbox poll; the device refuses any entry or checkpoint below it, making rollback cryptographically impossible (§5.3, D8).
- **SSF/CAEP** — the OpenID Shared Signals Framework / Continuous Access Evaluation Profile: the real-time backchannel carrying signed revoke/downgrade/deprovision events so they don't wait for token expiry or a poll cycle (§6).
- **SET (Security Event Token)** — a signed event (RFC 8417) delivered over the SSF/CAEP channel; fail-safe/revoke-only, never a grant (§4.3, §6).
- **SPIFFE kinds** — the principal-type segment of a `spiffe://wendy.sh/tenant/<uuid>/<kind>/<name>` identity: `operator` (human), `device`, `signer` (pre-existing codesign OIDC-keyless artifact-identity flows, distinct from the actor-identity model), `service` (machine/service-account, D17) (§4.2, §10 item 7/D17).
- **enrollment token / EAB key** — a device- and tenant-bound, single-use token pki-core mints on an operator-signed request relayed by cloud; for Tiers A/B it *is* the ACME External Account Binding key redeemed at first touch (§5.4).
- **device tiers A/B/C** — a capability/trust + (re)enrollment axis set by the hardware envelope: A = hardware attestation, self-recovers unattended; B = held key, no/weak attestation, needs operator approval post-expiry; C = constrained protocol/crypto envelope, recovery tracks whichever of A/B its attestation capability matches (§5.4).
- **`field_mode` / `offline_bundle`** — deployment-axis flags orthogonal to device tier; field mode lengthens a device's issued cert validity window (live-checked at renewal) without escalating any entitlement (§5.4, D16).
- **platform cap** — the hard ceiling on issued authority, stored in pki-core config, changeable only by Wendy platform admins, unreachable from any cloud-plane path; the sole bound on guarantee (B) escalation (§8).
- **tenant ceiling** — the per-tenant authorization bound cloud sets, itself bounded by the platform cap; a per-request grant can never exceed `min(requested, tenant ceiling, platform cap)` (§5.6).
- **grant** — a cloud-signed assertion ("principal P may do X, scope S, ≤ cap"), auditable and non-repudiable; never rides the fail-safe-only SSF signal channel (§4.3).
- **entitlement** — a `entitlement:{category}:{permission}:{effect}` string (deny-wins) baked into a device-facing credential so an offline enforcement point can decide without a live authz call; vocabulary = the wendy-agent gRPC method set ∪ cloud-defined entitlements (§4.2).
- **TSA (RFC 3161)** — the Time-Stamping Authority pki-core operates, chaining to the platform trust anchor; timestamps postbox entries and head checkpoints, proving an operator cert's validity *at signing time* even after it later expires (§4.4, §5.3, D9).
- **trusted time / anti-rollback floor** — a device's authenticated wall-clock source (NTS/Roughtime, or a pki-core-signed fallback seeded at enrollment) plus a monotonic high-water mark that never moves backward; unestablishable trusted time fails safe (hold state, alert) rather than guessing (§4.4, D12).
- **inter-service fabric vs. SSF signal channel** — "inter-service backchannel/fabric" (§11) is the private transport between the four control-plane services; "SSF/CAEP signal channel" (§6) is the semantic revoke/downgrade layer that rides on top of it. Use "SSF signal channel" and "inter-service fabric" to keep the two unambiguous (§11).
- **workload identity** — the transport-level identity that names *which service* is calling on the inter-service fabric (GCP-WI-OIDC token or mTLS peer); it never conveys a principal's authority (§11.1, §11.4, D11).
- **`tenant_uuid` claim vs. `org_id` slug** — `tenant_uuid` is the immutable, set-once-at-provision realm↔tenant binding carried as a token claim and used for tenant resolution; `org_id` is the human-facing, renameable realm slug and must never be used for identity mapping (§5.2, §9).
- **sender-constrained token** — a token bound to a key the holder possesses (`cnf.jkt` DPoP or `cnf.x5t#S256` mTLS-bound), so a stolen bearer token alone cannot be used — the only bearer-ish artifact the contract permits; there is no pure, copy-pasteable PAT (§4.1, D17).
- **step-up** — a fresh human factor (FIDO2/passkey tap) required to produce an operator-signed change request for a high-impact action; never silently refreshable (§5.1, §5.3).
- **correlation_id** — a single, cross-service-stable trace id, one per end-to-end flow: adopted from an inbound request, minted only at true origin, propagated unchanged, and persisted into every audit record and emitted signal (§11.2).
